Core Concepts

Review Storage

Reviewed marks, comments, questions, AI artifacts, and session state are stored as files on disk. By default they live in managed application data — not in your repository — and are shared between the terminal and desktop apps per repo, branch, and view.

Why managed storage?

Keeping review sidecars out of your working tree means they never clutter git status, never need a .gitignore entry, and never risk being committed by accident. Both front ends resolve the same path for a given tab, so a review you start in the desktop app continues seamlessly in the terminal.

Where the root is

PlatformStorage root
Linux~/.local/share/easy-review/v1/
macOS~/Library/Application Support/easy-review/v1/
Windows%APPDATA%\easy-review\v1\

Layout for local diff modes

Each local diff mode — branch, unstaged, staged and history — gets its own view bucket directory under the repo and branch. (The number in front of a mode in the tab bar is its position in the visible list, and that list grows when a tab knows its PR number, so a mode's number is not fixed.) 

<root>/repos/<repo-slug>/branches/<branch-slug>/view-buckets/<bucket>/

where <bucket> is branch, unstaged, staged, or history, and the repo and branch slugs end in a short hash so names that sanitize alike stay apart. For example, on Linux for the easy-review repo on main, branch diff:

~/.local/share/easy-review/v1/repos/easy-review-<8 hex>/branches/main-<8 hex>/view-buckets/branch/

Layout for PR diff mode

Pull request reviews are keyed by owner/repo and PR number, so a local clone and a remote PR tab share one location:

<root>/repos/<owner-repo-slug>-<8 hex>/prs/pr-<N>/

The <repo-slug> comes from the origin remote name (falling back to the repo folder name). Slashes in branch names become -, and the trailing hash keeps names that sanitize alike in separate folders.

Each JSON sidecar stores a SHA-256 diff_hash of the diff it was generated against. When the diff changes, the matching AI data is dimmed with a stale warning. Writes are atomic (write to a temp file, then rename), so a crash mid-write never corrupts your data.

External tools

Review files live only under managed storage. Point an external tool or agent that writes sidecars at this branch's view bucket; the layout is above.

Migration from older versions

Earlier versions scattered sidecar dotfiles in the repo root, then consolidated them into a repo .er/ directory. Nothing copies either of those into managed storage: a legacy repo .er/ or ~/.cache/er/ directory is left where it is, and a current build starts from empty for that branch. An existing .er/ is ignored.

Tests & overrides

Set ER_STORAGE_ROOT=/tmp/... to redirect managed storage — primarily used by the test suite.

Cleaning up

From the terminal, z clears the questions and notes you wrote, and Z clears the AI review sidecars (review.json, order.json, checklist.json, summary.md). Both ask for confirmation first.

To remove all Easy Review data and apps from the machine, use er uninstall or Desktop Settings → Uninstall — see Installation → Uninstalling.
