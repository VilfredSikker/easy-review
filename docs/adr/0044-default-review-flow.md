# The default review flow owns one prepared diff and waits for Deep acceptance

On 2026-10-18, the product decision was that one click starts triage, with no pull request refresh trigger. Quick runs general review then seeded arbiter verification; Standard adds triage-selected experts before seeded verification; Deep requires cost confirmation, runs an arena, and waits for explicit result acceptance. The engine will keep orchestration in memory and advance it while polling exact task IDs, because durable flow state is not needed to resume safely and a kind/target match cannot establish ownership. Every stage uses one prepared generation and its captured diff hash; Quick and Standard overlay arbiter verdicts without rewriting producer findings, while Deep imports nothing until acceptance.

The flow captures its bucket and inputs so navigation cannot redirect work. An App-level bucket lease excludes conflicting app-managed writes until owned tasks drain and the arena registry entry is released; terminal cancellation or failure does not itself make the bucket available. This lease does not coordinate a second process. At the review boundary, raw arena reviewer IDs normalize to lens IDs. Provider counts describe independent raisers; arbiter grading does not add a raiser. This keeps producer identity, provider attribution, and verification distinct. Project review-ignore filtering is applied before hashing, so all stages share the same filtered generation.
